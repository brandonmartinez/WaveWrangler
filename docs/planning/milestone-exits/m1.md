## 7. Unsupported and runtime limits

- **Claimed host only.** No macOS 26, 16 GB, 8 GB or Intel claim. CI builds with Xcode 26.6 / SDK 26.5 but runs no GUI tests.
- **Ad-hoc signing.** Builds carry Xcode-injected `get-task-allow`; no Developer ID, notarization or clean-install proof (WW-041).
- **Sandbox.** WWSources and WWPersistence tests run unsandboxed. Sandboxed panel grant/regrant/relaunch: <<PENDING: `M1-REF-020` / `M1-DUR-029` GUI evidence>>. Under the sandbox, L2 (unreachable) and L3 (needs permission) can't always be told apart; Grant Access works from both ([#60](https://github.com/brandonmartinez/WaveWrangler/pull/60)).
- **No cross-device recovery.** Priors, C2b checkpoints and the pending-edits journal are device-local (Q1). OFF keeps no crash snapshot (Q3).
- **Coordination is not a lock**; the base check is not a provider compare-and-swap. AppKit "Save Anyway" after an external change hits the base check (conflict), so the user must Save As, Duplicate or revert.
- **Identity evidence** relies on persistent per-volume file identifiers; APFS does not reuse them, but HFS+/exFAT may. Bookmark resolution never confirms identity.
- **Finder copies** of a `.wwshow` keep the same ShowID; the library shows an identity-collision state.
- **Library schema 2.** Schema 1 libraries get a provisional derived ID that never counts as identity; a real ID is assigned on the first schema 2 write, and the schema 1 bytes are kept as a migration backup. Older builds refuse schema 2 as unknown-newer.
- **ST-36 approximations.** The entry rule uses `UnavailableRecord.recordedAt`; recents keep the base order, because the model has no last-observed/last-opened times or location-hint history. Combining (keep everything) can bring back a removal made offline — by design nothing is dropped.
- **Stated channel in schema v1.** An Unknown channel uses index 0 as a placeholder that the UI always shows as "Unknown" ([#55](https://github.com/brandonmartinez/WaveWrangler/pull/55)). Relevant to M2.
- **Not implemented in M1 UI**, classified by the coordinator (2026-10-05) as P2 M2 follow-ups. Each becomes P0 M1 if the acceptance lane shows a core M1 task can't be completed without it. Items: Season [#69](https://github.com/brandonmartinez/WaveWrangler/issues/69), Duplicate Episode [#73](https://github.com/brandonmartinez/WaveWrangler/issues/73), Episode › Add to Collection [#68](https://github.com/brandonmartinez/WaveWrangler/issues/68) (collections hold shows only), Find [#71](https://github.com/brandonmartinez/WaveWrangler/issues/71), Rebuild Library Index progress UI [#74](https://github.com/brandonmartinez/WaveWrangler/issues/74) (the rebuild itself works), Resolve Unavailable Sources… ST-22 [#70](https://github.com/brandonmartinez/WaveWrangler/issues/70), Suggest Groups… [#72](https://github.com/brandonmartinez/WaveWrangler/issues/72), Review Location… [#75](https://github.com/brandonmartinez/WaveWrangler/issues/75), Pause [#76](https://github.com/brandonmartinez/WaveWrangler/issues/76). <<PENDING: acceptance-lane confirmation that none blocks a core task>>

## 12. Process deviations (disclosed)

- **Writer budget exceeded briefly.** During short review-fix rounds, 5–6 writer sessions were active at once; the budget is 4.
- **Reviewer budget exceeded twice.** Two windows had two concurrent read-only reviewer agents; the budget is 1.
- **Merge commits without the co-author trailer.** Merges from `main` into the persistence branch ([#56](https://github.com/brandonmartinez/WaveWrangler/pull/56)) lack the `Co-authored-by` trailer; they were not amended, to avoid force-pushing.
- **Fixture protocol not frozen before execution.** The WW-003 protocol was defined at the [#51](https://github.com/brandonmartinez/WaveWrangler/pull/51) merge, but no dated freeze record existed before the runs in #54, #56, #57, #58 and #60. Those runs used the seeded registry derivation and are labelled **pre-freeze**. [#62](https://github.com/brandonmartinez/WaveWrangler/pull/62) added a retroactive freeze `m1-freeze-1` (base `7087aa3`) with no gate, truth or count changes. Holdout claims cite only post-freeze runs.
- **Main briefly red between #60 and #61.** #60 gave each library a random `libraryID`, which broke a WWOrganizer test that compared against a fresh `LibraryModel()`. #61 fixed it. #62's PR CI failed on that test only, because its base predated #61.
- **Registry provenance metadata corrected after the freeze.** This PR changes only the `provenance` text of `M1-SRC-ON-002-REVIEW`: its generator dates from 2026-10-05, not 2026-10-04. Provenance is outside the frozen definition (recipe, truth, split, gate), so the freeze is unchanged.
- **Executed counts below the registry.** Many families had only single deterministic tests or small samples before the freeze (for example unknown-newer about 5 cases against 100/200; two-process 20 against 100; scale n=20 against 600). The coordinator chose post-freeze runs at the frozen counts (2026-10-05) rather than lowering any count.
- No data loss, source writes or protected-scope breaches resulted from these deviations. <<PENDING: confirm>>
