# M3 recovery checkpoint retirement: pre-code contract

**Owner:** Lead · **Status:** proposed for independent pre-code review; no implementation or acceptance evidence.
**Refs:** [WW-032 #27](https://github.com/brandonmartinez/WaveWrangler/issues/27), [WW-033 #30](https://github.com/brandonmartinez/WaveWrangler/issues/30), [WW-045 #41](https://github.com/brandonmartinez/WaveWrangler/issues/41), [rejected #339](https://github.com/brandonmartinez/WaveWrangler/pull/339), [M3 kickoff](../../planning/kickoffs/m3.md).

The user-directed #30 decision supersedes the automatic-resolution behavior proposed in earlier recovery drafts. #339 was independently rejected: a byte-identical replacement at the original path could strand a moved original without its offer, and failed post-save readback could still complete AppKit with `nil`. Neither that draft nor its earlier GUI evidence qualifies this design. This note specifies a gate for a **new eligible author**, not a patch or permission to merge a rejected branch.

## Invariant and observable outcomes

For each device-local unsaved edit checkpoint and offered recovery record, retain its exact stored record until **(a)** the person explicitly confirms **Discard** for that specific record and deletion succeeds, or **(b)** one completed, successful save is proven to have published the record's **exact `EditCheckpointRecord.snapshot` bytes** to the **same originating file identity**, followed by independent, coordinated readback of those bytes from that identity. Compare the serialized snapshot byte-for-byte, not decoded/equivalent models, show IDs, titles, revisions, fingerprints alone, or newly encoded bytes with a new publication ID. A save that publishes equivalent content but different bytes may succeed as a save; it cannot retire the checkpoint. Never treat a new show/copy with the same logical ID or data as the originating file.

No Save, Save As, Save a Copy, Revert, close/Don't Save, Undo/Redo, move, rename, replace, path equality, or copy completion *by itself* authorizes deletion. The only automatic retirement is the narrow, proven case (b), never an operation-type or path-based shortcut. This applies to pending and set-aside/offered edit checkpoints: no checkpoint-compaction or cleanup step may silently delete an unproven record. Keep other sessions' records, unreadable/problem records and the underlying storage through enumeration/read/verification errors; report the error rather than interpreting an empty or failed scan as "no offer." Hiding an offer in this window is not deletion; after relaunch the retained offer is discoverable. Explicit Discard operates only on the confirmed record, reports deletion failure and leaves it available on failure.

An origin-targeted save has two separate proof obligations before it can return success: (1) the normal complete publication and readback of the exact save candidate, including coherent document status, and (2) when attempting checkpoint retirement, proven origin-file identity continuity and readback of the exact checkpoint snapshot. A failed write, cancellation, readback failure, changed readback, lost identity, or uncertain receipt returns a **non-nil error to the NSDocument/AppKit completion**. The document remains edited, shows an accessible "save not confirmed"/failure state and retains every unproven checkpoint; no `Saved` announcement, library acknowledgement, successful close, or nil-error fallback. The bytes *might* have landed: report uncertainty honestly rather than claiming the old bytes remain; retry must re-establish base and identity before publishing again. A verified Save As/Copy to a different destination may succeed for that destination while leaving the original offer intact; destination verification failure is still a failed save. Close/Quit after failure cannot silently discard work or the offer. The ordinary explicitly confirmed Don't Save may close the window, but **does not delete** the checkpoint.

When a save already contains the checkpoint snapshot, the retained offer may be redundant. If there is no qualifying identity-and-readback proof for retirement, show a persistent, labelled message such as "These recovery changes may already be saved. Review them, or choose Discard to remove this checkpoint." Keep a keyboard/VoiceOver-reachable **Discard...** with confirmation and Cancel/Esc; do not auto-discard on apparent match, and do not claim that a matching *path* is proof. An older/different-base offer remains copy-only, not silently normalized into the live model. Restoring remains an undoable dirty edit; a refused restore leaves model, disk and offer unchanged.

## Proof boundary for the new implementation

- Bind each checkpoint to the originating show **file object** when the checkpoint is created/opened; capture a trustworthy filesystem/provider object identifier with its volume/provider namespace and an independently read baseline. Retain this binding outside `ShowDocumentModel` with the device-local record. A checkpoint lacking trustworthy origin identity (including legacy records) remains offerable but cannot be automatically retired. A bookmark, URL, standardized path, show ID, name, checksum or file size alone is not object identity. Never infer a match from equality of two reconstructed files.
- Coordinate saves and reads against the actual originating object. A rename/move may change its URL without changing identity; re-resolve under coordination and check that the targeted object is still the bound origin. A replacement at the old URL is another object even if its bytes match. An atomic safe-save may replace an inode: continuity then needs a verified transaction linking the old origin object to the new publication, not mere equality of the post-save path and bytes. If the platform/provider cannot supply this proof (including offline, conflict, changed file or reacquired bookmark), retain the offer and fail the origin-targeted save confirmation rather than manufacture identity.
- Capture checkpoint URL/key, record identity and immutable snapshot bytes, origin identity, restore generation and intended target at save start; serialize or generation-guard the completion. Require the same record and restore generation at completion, a successful publisher receipt, current origin identity, and a fresh coordinated read from that object with exact snapshot bytes **before** deletion. Recheck after readback, immediately before deleting just that record; another save, edit, Undo/Redo, Revert, move, replacement, cancellation or late callback invalidates the attempt. A destination Save As/Copy never borrows the origin's proof. Do not allow a pending automatic save to write the original behind a Save As/Copy panel.
- Keep record storage until deletion is positively acknowledged. A failed deletion is not success: preserve/re-offer what remains, report the error, and never let another record be swept up as cleanup. If AppKit clears its edited token after a write before post-save verification fails, restore the unsaved/dirty state before invoking the completion with a non-nil error; verify this behavior in a native lifecycle test. If AppKit cannot safely be kept dirty and open at that hook, **stop for an independently reviewed alternative save boundary** rather than weaken this invariant.

Implementation boundaries to audit include `ShowDocument.save`/`finishSave`, `writeSafely`, retry/adoption, Save As/Copy, `close`, Revert, `RecoveryStore` write/offer/discard paths, and offer presentation. Existing `resolveOfferRecordsAfterVerifiedSave`, copy-resolution, close-time deletion and `try?` recovery operations are **not** evidence for this contract. Keep source assets read-only and edit/map history nondestructive; recovery verification reads the small show/checkpoint document, **not media**. No media, model, provider or network processing is authorized by this note.

## Red-first verification matrix for the new author

Every row checks **stored record(s), visible/AX offer, live edited state, actual origin and destination bytes, AppKit completion error and close behavior** as applicable; run both autosave settings where relevant. Start with failing native/package regressions against the old behavior before implementing the new one.

| Case | Required result |
| --- | --- |
| Restore -> Revert -> unrelated Save; Undo/Redo before/during Save | Original checkpoint survives, restoration marks cannot select it for retirement, no unrelated save deletes it. |
| Save As with Autosave **OFF** (and ON); Save a Copy and open-as-separate-copy saved | Destination can be verified/saved; unchanged originating file and its offer survive; queued autosave cannot silently write the origin during the panel. |
| Rename/move original; put a byte-identical replacement at its old path; save via old path | Replacement never inherits origin identity, original's offer survives; origin-targeted verification reports uncertainty/error and remains dirty/open. |
| Move original and save through its newly resolved identity; atomic safe-save replaces inode | Retire only with positive old-to-new transaction continuity **and** exact checkpoint-byte readback; otherwise explicit error, dirty state, retained offer. |
| Origin offline/permission denied; provider changes origin or target during coordination | Error rather than path fallback; no deletion, no successful close/status/library acknowledgement; retry revalidates identity. |
| Successful write followed by failed, partial or changed origin readback | Non-nil AppKit completion, dirty/open and honest uncertainty, stored offer survives even if candidate may have landed. |
| Matching show ID/title/model but different object; equivalent model with different encoded bytes | No automatic retirement; a verified unrelated save may succeed while its offer remains with an accessible invitation to Discard. |
| Cancelled, overlapping or late save; failed checkpoint enumeration/deletion; two sessions' records | No stale completion or blank-list deletion; each record survives unless its own proof or confirmed Discard succeeds; failures stay visible. |
| Confirmed Discard vs Cancel/Esc; restore refused on changed inputs | Only the selected confirmed record is deleted; cancel/refusal preserves record and live/disk state; deletion errors remain actionable. |

**Gate, not evidence:** independent pre-code review must first agree on the identity/atomic-safe-save and AppKit dirty-completion feasibility. Then a different eligible author writes red-first tests and code, obtains independent cumulative review against `main`, and runs a fresh full `scripts/test.sh` on the **clean pushed exact final head SHA** (record SHA, host, one-minute load, pass/fail/skip counts). On that same committed SHA, build/verify/copy isolated synthetic Products to the physical Mac mini and run the affected `DocumentLifecycleUITests` (relaunch/restore, Undo/Redo, Save, close/revert, offer/Discard), `OfflineSaveKeyboardUITests` (OFF/ON failed-save, Save a Copy and close) and affected `CoreTasksKeyboardUITests`/`AlignmentInspectionUITests.testBlockedRecoveryContrastAudit` under the Mini GUI lease; add cases where existing classes lack coverage. Record host, classes/cases, pass/fail/skip, `.xcresult`, keyboard/VoiceOver path, role/label/value/focus/action/hit-region and blocked-state contrast. Historical #339 or ancestor runs do not transfer. **No production code, gate run, merge or issue acceptance is claimed by this design PR.**
