# M1 design sources — fetched Apple primary sources

**Owner:** Design. **Fetched:** 2026-10-04 (around 23:30 EDT) by Design, using `curl` against Apple's DocC JSON endpoints (`https://developer.apple.com/tutorials/data/...json`). These endpoints supply the content for the public HTML pages. Every row below returned HTTP 200, and Design extracted and read the text for each cited claim. "Displayed update" is the page's own `alert-date` metadata, not a re-verification date.

The other M1 design documents cite these rows with `[A#]` keys. Anything not traceable to a row here is marked **(unverified)** where it appears.

## Human Interface Guidelines

| A1 | [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) | 2025-06-09 | "Ideally, give people the option to enlarge text by at least 200 percent … either through custom UI, or by adopting Dynamic Type"; macOS default 13 pt / minimum 10 pt; WCAG AA contrast (4.5:1 up to 17 pt, 3:1 for 18 pt or bold); "if your app doesn't provide this minimum contrast by default, ensure it at least provides a higher contrast color scheme when … Increase Contrast is turned on"; "Convey information with more than color alone"; macOS control size 28×28 pt default / 20×20 pt minimum; offer alternatives to gestures; Full Keyboard Access, avoid overriding system shortcuts; minimise time-boxed UI; Reduce Motion: reduce automatic/repetitive animation, replace x/y/z transitions with fades. |
| A2 | [VoiceOver](https://developer.apple.com/design/human-interface-guidelines/voiceover) | 2025-03-07 | Descriptive labels for all key elements; unique titles and accurate headings; describe grouping/order; "Inform VoiceOver when visible content or layout changes occur" (AccessibilityNotification); support the rotor. |
| A3 | [Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars) | 2026-06-08 | "In general, show no more than two levels of hierarchy in a sidebar. When a data hierarchy is deeper … consider using a split view interface that includes a content list"; Show/Hide Sidebar in View menu; avoid hiding the sidebar by default; "Avoid putting critical information or actions at the bottom of a sidebar"; familiar SF Symbols; respect the system accent color. |

## SF Symbols name check (host observation, not a source)

On 2026-10-04, Design ran a non-GUI script that calls `NSImage(systemSymbolName:accessibilityDescription:)` on 74 candidate SF Symbol names. These included every name used in these design documents (a second pass extracted the names from the Markdown). **All resolved** on the current host (macOS 27.0.1, arm64). This does **not** prove availability on macOS 26; the acceptance suite requires an automated check on the deployment target (see [accessibility-acceptance.md](accessibility-acceptance.md#4-automated-structural-checks)).
