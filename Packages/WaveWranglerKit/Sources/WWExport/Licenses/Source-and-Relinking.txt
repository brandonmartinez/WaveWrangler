The development replacement path is a complete source rebuild/relink, not
replacing a dylib inside a signed application. Keep the public LAME ABI.
From a source checkout, validate the original library with:
python3 scripts/check-lame-source.py

After replacing/modifying the library sources, rebuild every codec consumer:
SWT_EXPERIMENTAL_MAXIMUM_PARALLELIZATION_WIDTH=2 swift test --package-path Packages/WaveWranglerKit --scratch-path .build/lame-relink --jobs 2 --filter WWExportTests
WW_JOBS=2 WW_DERIVED_DATA="$PWD/.build/LameRelinkDerivedData" scripts/build.sh Debug

Preserve the library user's rights, including reverse engineering for debugging
library modifications. Do not impose restrictions on replacement builds.
